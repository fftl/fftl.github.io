## 문제 상황

python에서 .env를 이용해 DB연결을 하던 도중 내가 설정하지 않은 환경변수 값이 나타나는 문제가 발생했습니다. 

(아래 상황은 재연을 위해 다시 설정하였습니다.)

### 상황 확인 
.env에 DB 연결에 사용할 USERNAME에 분명 my_db_user 라고 입력해놓고 DB연결 engine을 만들었습니다.


![[env 파일 에러-1770257723336.png]]

![[env 파일 에러-1770257785082.png]]

### 연결 확인
이제 연결 확인을 위해 engine에 간단한 select 문을 날려보았습니다.

![[env 파일 에러-1770257861622.png]]

그런데 연결은 실패했고, 다음과 같은 에러가 발생했습니다. 'LEE'@'~' 에 연결할 수 없다고 에러를 발생시키고 있었습니다.

![[env 파일 에러-1770258006646.png]]

하지만 위에서 봤듯이 분명히 저는 USERNAME에 my_db_user라는 값을 입력해놓았기 때문에 무슨 일이지? 라는 생각을 할 수 밖에 없었습니다.

### 원인 파악
원인을 파악하기 위해 .env의 경로도 확인해보고, 다시 출력해봐도 USERNAME은 다르게 나올 뿐이었습니다.

![[env 파일 에러-1770257589518.png]]

이제 이리저리 확인을 해보니 **PASSWORD와 HOST는 원하는대로 출력되고 있다는 사실을 발견**했습니다. 그럼 USERNAME 이 문제라는 건데, **왜 LEE라는 값이 나오고 있는지 추측**해보기 시작했습니다.

사실 LEE라는 값은 제 PC의 이름이기도 했습니다. 혹시 **USERNAME이라는 환경변수가 예약어 처럼 사용되고 있는건** 아닐까? 라는 뱡향을 잡았습니다.

그리고 확인해보니 .env에 정의를 해놓더라도, **시스템 환경 변수가 우선**이기 때문에 다음과 같이 지정된 환경변수의 경우 그대로 사용되고 있는 것을 확인하였습니다.

![[env 파일 에러-1770258407672.png]]

### 해결 방법
가장 간단한 해결 방법을 사용하기로 했습니다. 다시 환경변수 앞에 DB를 붙이는 것이었습니다. 

![[env 파일 에러-1770258537327.png]]

'왜 중복되는 DB를 굳이 붙여야 할까?'라는 생각 때문에, 지웠다가 조금의 시간을 소비하게 되었지만 간단하지만 재미있는 발견이었던 것 같습니다.
