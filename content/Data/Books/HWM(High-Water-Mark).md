HWM의 개념에 대해 정리해보고자 합니다.

HWM란? 테이블에서 데이터가 한 번이라도 입력되었던 블록의 최고 위치를 표시하는 경계선입니다. 

예시로 만약 10000개의 데이터를 담을 수 있는 공간에서 9000개의 데이터를 담았다가 바로 8000개의 데이터를 삭제한다고 하더라도 HWM은 이미 9000으로 기록되어 있습니다. 이러한 상황에서 만약 Full Table Scan을 하게 된다면 Full Table Scan은 HWM 영역까지 읽어내기 때문에, 비효율적인 상황이 발생하게 됩니다.

또한 Insert를 진행할 때, 일반 Insert의 경우 Freelist에서 블록을 찾아내는데, 이 Freelist는 HWM 아래(이미 사용했던 블록들)에서 빈 공간이 존재하는 블록들을 모아놓은 공간입니다. 이 Freelist에서 블록을 찾아 입력을 하는 형식이지만, Direct Path Insert의 경우 HWM의 위에서, 즉 아직 사용된 적 없는 블록들을 이용하기 때문에 탐색의 시간도 필요 없이 바로 입력할 수 있는 이점이 있습니다.

따라서 가진 데이터에 비해 HWM가 높은 경우 성능에 문제가 생길 수 있는데 이를 조정하는 방법은 다음과 같습니다.

```sql
-- 1번 TRUNCATE (HWM 초기화, 모든 데이터 삭제)
TRUNCATE TABLE 직원;

-- 2번 테이블 재생성
ALTER TABLE 직원 MOVE;

-- 3번 HWM 축소 (10g 이상)
ALTER TABLE 직원 SHRINK SPACE;
```

> ALTER TABLE 직원 MOVE; 의 MOVE는 새로운 저장공간을 할당받아 테이블을 재생성 한다고 볼 수 있습니다. 빈 공간 없이 데이터를 compact하게 재배치하고, 기존 공간은 해제 합니다. HWM이 실제 데이터 크기 만큼으로 재설정 됩니다.

MOVE의 특징

 **장점:**
- HWM 재설정 (낮아짐)
- 단편화(fragmentation) 제거
- 저장 공간 회수
- Full Table Scan 성능 향상

**단점:**

- 테이블 전체를 복사하므로 시간이 오래 걸림
- 테이블 락(lock)이 발생 (다른 작업 불가)
- **인덱스가 UNUSABLE 상태가 됨** ← 매우 중요!
