
# 읽기 방법
```
SELECT STATEMENT                     
  NESTED LOOPS                      ← 5. 조인 수행
    TABLE ACCESS (BY INDEX ROWID)   ← 4. ROWID로 테이블 접근
      INDEX (RANGE SCAN)            ← 1. 인덱스 스캔 (제일 먼저)
    TABLE ACCESS (BY INDEX ROWID)   ← 3. ROWID로 테이블 접근
      INDEX (UNIQUE SCAN)           ← 2. 인덱스 스캔
```

**읽는 순서**: 1 → 2 → 3 → 4 → 5

## 쉽게 기억하는 방법

1. **가장 들여쓰기 된 곳**부터 시작
2. **같은 레벨**이면 위에서 아래로
3. **데이터 흐름**을 따라가면서 읽기

지금껏 실행 계획도 제대로 모른 채 책을 쭉 읽어왔는데, 더 이상 그냥 넘어가면 안될 것 같아 claude에게 물어보고 이해해보았습니다. 그리고 이해한 바를 바탕으로 문제를 만들어 달라 했고 한번 풀어보았습니다.

# 문제

```sql
Operation                           Rows    Bytes   Cost
SELECT STATEMENT                      50    3,500    850
  SORT (ORDER BY)                     50    3,500    850
    HASH JOIN                        150   10,500    820
      TABLE ACCESS (FULL) DEPT       100    2,000     10
      HASH JOIN                      500   30,000    800
        TABLE ACCESS (BY ROWID) EMP  800   40,000    120
          INDEX RANGE SCAN IDX_DEPT  800             100
        TABLE ACCESS (FULL) SAL    2,000   60,000    680
```

- **실행 순서대로** 번호 매겨보세요 (어떤 게 먼저?)
- **데이터 흐름**을 설명해보세요 (Rows가 어떻게 변하는지)
- **Cost 증가 과정**을 추적해보세요
- **병목 구간**이 어딘지 찾아보세요

# 풀이

```sql
Operation                           Rows    Bytes   Cost
SELECT STATEMENT                      50    3,500    850 -8
  SORT (ORDER BY)                     50    3,500    850 -7
    HASH JOIN                        150   10,500    820 -6
      TABLE ACCESS (FULL) DEPT       100    2,000     10 -4
      HASH JOIN                      500   30,000    800 -5 
        TABLE ACCESS (BY ROWID) EMP  800   40,000    120 -2 
          INDEX RANGE SCAN IDX_DEPT  800             100 -1
        TABLE ACCESS (FULL) SAL    2,000   60,000    680 -3
```

- 1. **실행 순서대로** 번호 매겨보세요 (어떤 게 먼저?) 코드 옆에 표시.
- 2. **데이터 흐름**을 설명해보세요 (Rows가 어떻게 변하는지)
- 3. **Cost 증가 과정**을 추적해보세요 
	- **2,3번 풀이**
	- 1. INDEX RANGE SCAN, idx_dept를 이용해 index range scan을 진행 800 rows를 가져왔고, 100의 cost를 사용
	- 2. TABLE ACCESS, 가져온 index range를 이용해 emp 테이블에 table accesss를 진행 800 rows를 찾았고, 20 cost를 추가로 소모 총 120 cost 상태
	- 3. TABLE ACCESS, sal 테이블에 full 즉 전체를 가져오기 2000 row를 가져왔고, 680 cost 소모
	- 4. TABLE ACCESS, dept 테이블의 모든 rows를 가져옴 10 cost 사용
	- 5. HASH JOIN, 1,2번의 작업 120cost 와 3의 작업 680cost를 합쳐 800cost로 표현, Hash join을 통해 500 row로 추려냄
	- 6. HASH JOIN, 5번의 10cost와 6번의 800cost를 합쳐 820cost로 표현, 둘을 Hash join을 이용해 150 row로 줄여냄
	- 7. SORT (ORDER BY), 6의 HASH JOIN 결과물을 정렬함 30 cost가 들어 850cost가 됨
	- 8. SELECT STATEMENT, 결과를 반환!
- **병목 구간**이 어딘지 찾아보세요
	- 3번 과정 TABLE ACCESS (FULL) SAL 과정이 문제였던 것 같습니다. 전체 850 cost중 680 cost의 비용이 여기서 발생했습니다.
