### 한국사회보장정보원 전산직
---
(전산직) 본인이 보유한 전산 직무 핵심 기술을 제시하고, 이를 활용해 구체적 성과를 낸 경험을 작성해 주십시오. 또한, 그 경험을 통해 얻은 교훈과 기관 전산 업무 적용 방안을 함께 작성해 주십시오. (1000자 미만)

데이터 수집과 가공, 관리 능력, 그리고 이를 구현하는 소프트웨어 개발 능력이 저의 핵심 기술입니다.

SW 교육과정에서 3회의 팀 프로젝트를 수행하며 2회 우수상을 수상했습니다. 주로 백엔드 개발과 인프라 구축, 데이터 수집을 담당하며 기술적 기반을 쌓았고, 특히 보드게임 추천 프로젝트에서 API 분석과 대규모 데이터 가공을 경험한 것이 데이터 엔지니어링에 대한 관심으로 이어졌습니다.

이후 직접 전력 사용량 데이터 분석 프로젝트를 기획하며 본격적으로 역량을 발휘했습니다. 한국전력공사 공공 API에서 가구평균 전력사용량을 수집하고, 이상치 탐지와 보정을 포함한 전처리 파이프라인을 설계했습니다. Apache Airflow로 수집부터 가공, 적재까지의 ETL 워크플로우를 자동화하고, MySQL에 적재된 데이터를 BigQuery로 이관하여 분석 환경을 구성했습니다. 팀 프로젝트에서 쌓은 협업 경험과 Java, Spring 기반 시스템 설계 역량이 이 프로젝트의 전체 아키텍처를 구성하는 데 큰 도움이 되었습니다.

이 경험을 통해 얻은 핵심 교훈은, 데이터는 수집 자체보다 활용 가능한 형태로 정제하는 과정이 가치를 결정한다는 점입니다. 원천 데이터의 품질과 구조가 이후 모든 분석과 의사결정의 신뢰도를 좌우하기에, 데이터 정합성 확보에 각별히 주의를 기울이게 되었습니다.

한국사회보장정보원은 데이터를 통해 찾아낸 가치가 수많은 국민의 복지에 직접 적용되는 곳입니다. 다양한 출처의 데이터를 수집하고 가공한 경험과 파이프라인 구축 역량을 바탕으로, 사회보장정보시스템의 데이터 연계 및 품질 관리에 기여하는 전산 인력으로 성장해 나가겠습니다.

저의 핵심 장점은 반복적인 업무를 체계적으로 구조화하여 효율적인 처리 기반을 만드는 능력입니다. 같은 작업이라도 매번 처음부터 수행하는 것이 아니라, 패턴을 파악하고 재사용 가능한 구조를 먼저 설계하는 습관이 있습니다.

이 장점을 기술적으로 강화하기 위해 꾸준히 노력해 왔습니다. SW 교육과정에서 팀 프로젝트를 진행할 때에는 Spring Boot 서버와 React 프론트엔드의 배포가 매번 수작업으로 이루어지는 비효율을 줄이기 위해, Github과 Jenkins, Docker를 활용한 자동 배포 시스템을 구축하여 반복되는 배포 업무를 제거했습니다. 

한국전력공사 API를 활용한 시계열 데이터 분석 프로젝트에서는 이상치가 빈번하게 발생하는 원시 데이터를 매번 수작업으로 정제하는 대신, 이상치 탐지와 보정을 자동으로 수행하는 전처리 파이프라인을 설계하여 분석 작업의 효율을 크게 높였습니다. 또한 SQLP 자격 학습을 통해 인덱싱 전략과 조인 최적화 기법을 익히고, MySQL과 Oracle 환경에서 실제 데이터를 다루며 반복 수행되는 쿼리의 실행 계획을 분석하고 개선하는 실무적 감각을 키워 왔습니다.

한국사회보장정보원은 행복이음, 범정부 사회보장정보시스템 등 대규모 시스템을 통해 수십 개 기관의 복지 데이터를 연계하고 처리하고 있습니다. 이 과정에서 각 기관마다 상이한 데이터 양식을 공통 형식으로 전환하는 작업이 반복적으로 발생할 것이라 생각합니다. 이러한 전환 과정을 자동화하여 데이터 수집과 연계에 소요되는 시간을 단축하고, 지속적으로 유입되는 데이터의 품질을 점검하여 원천 데이터의 신뢰성을 높이는 방안을 마련하겠습니다. 나아가 축적된 데이터에서 새로운 가치를 발견할 수 있는 안목을 키워, 한국사회보장정보원의 보건복지 정보시스템 통합에 기여하고 싶습니다.

SW 교육과정에서 보드게임 추천 서비스를 개발하는 5인 팀 프로젝트를 진행하던 중, 추천 알고리즘 구현을 담당한 팀원의 작업 진척이 거의 없는 상황이 발생했습니다. 해당 팀원은 본인의 업무 대신 다른 팀원들의 작업을 도와주며 시간을 보내고 있었습니다. 다른 팀원들도 이를 인지하고 있었지만 직접적인 대화를 피하고 있었고, 시간이 지날수록 팀 전체의 분위기와 일정에 영향을 미치기 시작했습니다.

저는 이 상태가 지속되면 프로젝트의 완성도와 팀원 간 신뢰가 무너질 수 있다고 판단하여, 해당 팀원과 개인적으로 대화를 시도했습니다. 대화를 통해 협업 필터링과 콘텐츠 기반 필터링을 조합한 추천 알고리즘 구현이 예상보다 훨씬 어려웠고, 그로 인한 부담감이 커서 오히려 손을 놓게 된 것임을 알게 되었습니다. 저는 이 상황을 팀 전체에 공유한 뒤 함께 해결 방향을 논의했습니다. 핵심은 기능의 우선순위를 재조정하는 것이었습니다. 복잡한 알고리즘 대신 가중치 기반의 단순화된 추천 방식으로 전환하고, 확보된 시간을 전체 서비스의 완성도를 높이는 데 집중하기로 했습니다. 방향이 명확해지자 해당 팀원도 다시 적극적으로 참여하게 되었고, 결과적으로 팀이 목표했던 수준의 서비스를 기한 내에 완성할 수 있었습니다.

이 경험을 통해 협업에서의 문제는 회피할수록 커지고, 직접적인 소통이 해결의 출발점이라는 것을 배웠습니다. 또한 문제의 근본 원인을 파악한 뒤 모든 구성원이 납득할 수 있는 현실적 대안을 함께 도출하는 과정이 팀의 신뢰를 회복하는 핵심이라는 점을 깨달았습니다. 한국사회보장정보원에서도 여러 부서와 기관이 연계된 시스템을 운영하는 과정에서 다양한 이해관계와 기술적 난제가 발생할 것이라 생각합니다. 이때 문제를 정면으로 마주하고, 관계자들과 열린 소통을 통해 합리적인 해결책을 찾아가는 자세로 업무에 임하겠습니다.

결과적으로 4일 이상 소요되던 수집 과정을 수 시간으로 단축하고, 두 개의 이기종 데이터 소스를 하나의 통합 데이터셋으로 구축하여 프로젝트를 기한 내에 완성할 수 있었습니다. 이 경험을 통해 제한된 자원 안에서는 문제를 작은 단위로 분해하고 각 단계의 비효율을 정확히 짚어내는 것이 가장 효과적인 접근이라는 것을 배웠습니다. 한국사회보장정보원에서 다수 기관의 복지 데이터를 연계하고 처리하는 업무에서도, 데이터 수집과 정제의 효율성을 높이고 이기종 데이터 간 정합성을 확보하는 데 이 경험을 적용하겠습니다.

### 연합인포맥스 데이터 어소시에이트
---

자유양식 입니다. (제한 없음)

데이터를 다루는 일에 처음 재미를 느낀 것은 SW 교육과정에서 보드게임 추천 서비스를 개발하면서였습니다. 당시 저는 데이터 수집을 맡았는데, 해외 보드게임 사이트의 API 구조를 분석해 필요한 데이터를 수집하고, ID 체계가 서로 다른 두 개의 데이터 소스를 이름 기반 매칭으로 통합하고, 영문 데이터를 한글화하는 작업까지 수행했습니다. 처음에 4일 이상 걸리던 수집 과정을 파이프라인을 다시 설계해 수 시간으로 줄였을 때, 데이터를 어떻게 다루느냐에 따라 프로젝트 전체의 속도와 품질이 달라진다는 것을 몸으로 느꼈습니다.

그 뒤로 데이터 엔지니어링에 본격적으로 관심을 갖게 되어 전력 사용량 데이터 분석 프로젝트를 직접 기획했습니다. 한국전력공사 공공 API에서 가구평균 전력사용량을 수집하고, 이상치 탐지와 보정을 포함한 전처리 파이프라인을 설계했습니다. Apache Airflow로 수집부터 가공, 적재까지 ETL 워크플로우를 자동화했고, MySQL에 적재한 데이터를 BigQuery로 이관해 분석 환경을 구성했습니다. 교육과정에서 팀 프로젝트를 하며 쌓았던 Java와 Spring 기반의 백엔드 개발 경험, Docker와 Jenkins를 활용한 CI/CD 파이프라인 구축 경험이 이 프로젝트의 전체 구조를 잡는 데 큰 도움이 되었습니다.
